## Rules (deleting is hard to undo: be conservative, log everything)
1. FIRST write `Logs/cleanup/PLAN.txt`: every candidate, its size, its category, and why it is safe. Then delete only category A.
   Everything else goes to the report for the owner. Save the manifest of what you deleted (path, size) to `Logs/cleanup/DELETED.txt`.
2. Do it with the Unity lock held (`source tools/unity-lock.sh; unity_lock_acquire`) so no build/player is mid-write. Never touch a
   file a running process has open. Do not use `pgrep -f` inline.
3. NEVER delete: anything git-tracked (check `git ls-files`), `.git`, `Assets/`, `ProjectSettings/`, `Packages/`, uncommitted work
   (`git status`), `PlaySettings.json`/`PlayerConfig.json`, saved worlds/saves, the current `Library/` (re-import takes very long on this
   Mac), `tools/`, `*.md` docs, anything under `tools/overnight/` (queue, done, blocked, HANDOFFs, `.LEAKED`, `.patch`), and any image
   or file referenced by the Queue decisions doc, `tools/archive/README.md`, TASKS.md, KNOWN_ISSUES.md, a HANDOFF or a completion
   doc (grep the repo for the path/name before deleting a screenshot).
4. Category A (delete): regenerable and stale.
   - `Builds/` standalone builds and their scratch (`*_BurstDebugInformation_DoNotShip`, `*_BackUpThisFolder_ButDontShipItWithYourGame`)
     EXCEPT the newest build of each distinct build folder name (keep the most recent, delete older copies); never a build modified
     in the last 24 h.
   - Logs under `Logs/` older than 7 days that no doc references (keep `Logs/overnight/runner.log` and the last 7 days of everything).
   - Root clutter regenerated by test runs: `TestResults*.xml` except the newest `TestResults_all.xml`, `unity_test*.log`, `build.log`,
     `fluid_tiled_build.log`, `Il2CppOutputProject` only if it is untracked and regenerated by builds (it is, but confirm it is
     not git-tracked first).
   - Screenshots: only untracked intermediates NOT referenced anywhere: `try*` folders, `*.out`, `*_spikes.csv`, `log_*.txt`, retry dirs,
     leftover per-pose frames of rejected attempts. Keep every image the docs or archive reference and every task's final sheets.
   - macOS caches of dev tools that rebuild themselves: Unity's global caches (`~/Library/Unity/cache`, `~/Library/Caches/com.unity3d.*`),
     Xcode `DerivedData` and old `iOS DeviceSupport`, `~/Library/Caches/pip`/`Homebrew` downloads (`brew cleanup -s` is fine), npm
     `_cacache`, and the Trash. Do NOT clear browser, Claude, or app data caches wholesale.
5. Category B (report only, owner decides, put sizes in the report): the sibling `../VoxelTerraria_compare` (another session uses
   it, so touch nothing there), `../Wortis-Dev`, `../WortisBuild`, `../VT_gemini2`, old Unity editor versions in `/Applications`,
   large files elsewhere under `~` (list the 30 biggest with `find ... -size +500M` / `du`, excluding the project), Time Machine
   local snapshots (`tmutil listlocalsnapshots /` and the size they hold), and anything you are not sure about. Also report Screenshots
   by size per task folder so the owner can pick what to archive.
6. If after category A free space is still under 15 GiB, finish with STOP_FOR_OWNER and a short ranked list of category B items.
   If it is over, end normally. Either way, put before/after free space (`df -h /`) in the HANDOFF.
