TASK 130 -- what each outcome makes us do, written BEFORE the measurement (PERF_SHELL_MARCH_PLAN.md §3, §5)

Definitions (per pose, warm, p50 ms from one cost-split launch, F X X F per arm, saved = FULL - arm):
  M  = FULL - shellmarch_off            the in-kernel shell march (+ far march after it)        (93b re-run: 13.7 / 19.1)
  S1 = shellsplit - shellmarch_off      the same march alone in CSShellProbe (+ ~0.1 ms flag write / dispatch)
  S2 = shellsplit2 - shellsplit         a second, warm-cache march of the same rays in the probe
  eff = E3's sum / (32 x max) of shell iterations per 32-lane SIMD (iteration-weighted)

Validity first: the probe's [shell shellsplit] counters (primary rays, iterations, dir / page reads) must equal FULL's
at the same pose (same rays, same march). If they do not, the probe is wrong: fix it, do not interpret the times.

E1 (H1, mega-kernel context):
  S1 <= M/3            -> row A: the march is cheap alone; the big kernel's context is most of its cost -> R1 (shell pre-pass kernel),
                          plus R2 if E3 = B.
  S1 >= ~2M/3          -> row B: the march is slow by itself (H2/H3/H4) -> read E2 and E3.
  M/3 < S1 < 2M/3      -> in between: both matter; the rule still picks by E1 first: count it as A only if S1 <= M/2
                          (more than half the cost is context), else B. Said so in the report.
  (Note: the far march after a shell no-hit is also skipped in shellmarch_off and NOT run by the probe, so S1 slightly
   understates what R1 would leave; 93b3 measured that far march at ~0 ms, so it does not move the row.)

E2 (H2 memory latency vs H3/H4 execution), only read when E1 = B:
  S2 >= 3/4 x S1       -> row A: execution-bound (ALU / divergence); memory-layout work dropped -> R6 (kernel diet), + R2 if E3 = B.
  S2 <= 1/3 x S1       -> row B: first-touch misses dominate -> R5 (chunk-state bitmap per shell), then R4 later.
  between              -> mixed: say so; the nearer row decides.

E3 (H3 divergence), no timing:
  eff >= 0.6 at both poses -> A: divergence is out; R2 not worth designing.
  eff <= 0.35 at walk_open -> B: R2 (compaction / sort by ray kind) is the walk_open lever (needs R1).
  walk_near expected high; if walk_near is low too -> the per-step branch union (R6).

The plan's rule (§5 step 2), applied to the result:
  E1 = A                -> R1 (then R2 if E3 = B)
  E1 = B and E2 = B     -> R5
  E1 = B and E2 = A     -> R6, plus R2 if E3 = B
